# TRAE 桌面端多账号签到设计

## 目标

用户首次为每个 TRAE 桌面账号导入一次本机登录凭证。之后，一键签到和定时签到直接对每个已启用账号调用 TRAE 官方签到接口，无需再切换当前 TRAE 客户端账号。

## 凭证与安全

- 每个账号保存 `token`、`refreshToken`、Token 过期时间和设备 ID。
- 凭证仅保存在本机应用数据中，并使用 Electron `safeStorage` 加密后写入存储。
- 渲染进程、账号列表、日志、通知和错误信息都不得读取或输出凭证内容。
- 旧的 Cookie 字段仅用于兼容已有数据；新的桌面账号不依赖 Cookie。

## 导入账号

1. 用户在 TRAE 客户端中切换到目标账号。
2. 在本工具的添加账号窗口中点击“导入当前 TRAE 桌面账号”。
3. 主进程读取当前 TRAE 本地登录信息与设备 ID，取得账号 ID 和显示名，并加密保存凭证。
4. 若账号 ID 已存在，则更新该账号的凭证，不创建重复记录。

## 签到和续期

1. 单账号、批量和定时签到均使用该账号保存的凭证。
2. 签到前，当 Token 临近过期或服务端提示认证失效时，使用 refreshToken 刷新 Token，并写回加密凭证。
3. 然后调用状态接口；已签到返回“今日已签到”，否则调用领取接口并显示“签到成功”。
4. refreshToken 失效时，只标记该账号为“凭证已失效，请重新导入”；其他账号继续处理。

## 界面与兼容性

- 添加账号弹窗的默认入口为导入桌面账号；旧 Cookie 输入不再作为默认流程。
- 账号卡片显示桌面凭证状态：有效、即将过期或需要重新导入。
- 设置页面移除 Webview/自定义 API 签到模式和 Cookie 指引，改为说明桌面接口、多账号导入和凭证失效处理。
- 服务端返回的英文 `success` 在界面统一显示为“签到成功”。

## 验证

- 为凭证加密、导入去重、凭证失效和成功消息归一化编写自动化测试。
- 使用模拟凭证验证批量签到会为每个账号发送其自己的认证信息。
- 运行现有全部测试和生产构建；不在测试中发送真实领取请求。
